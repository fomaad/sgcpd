# 12.25節 実験結果まとめ — safety-model-guided abstraction and refinement（ログ0067、1本での予備実験）

## 目的

CPD検証パイプライン全体は、safety model guided abstraction and refinement の一種である。これまでJAMA C&Cモデルを安全性判定に使ってきたが、代わりにRSSを使うとどうなるか、また「特徴を考えない」ベースラインとの比較を、ログ0067（1本）で試した。

## 議論を経て確定した理解

- **「車両物理サイズ基準」は一様格子の特殊系。** 車両サイズだけを根拠にするなら、near/farで異なるセルサイズを使う理由がない。徹底するなら、車両サイズ由来の1つのセルサイズを全域に一様に使うべきである。
- **「near/far」は計量格子の粒度の話ではない。** 本来の意図は述語的抽象化(predicate abstraction)——(1) 近傍は安全性モデル自身の状態変数（risk知覚フレームの前後、接触の有無）で区切り、(2) 遠方（安全性モデルが注意を払わない範囲）は位置によらず**単一の箱**に潰す、というもの。
- **「あるモデルで純粋な抽象化が別モデルで純粋とは限らない」ことは重要ではない。** 各安全性モデルの抽象化は、それぞれの文脈の中だけで解釈・使用されるため。重要なのは、各抽象化が自分自身のonsetに対してpureであることと、モデル間の箱数・判定結果そのものの比較。
- `gcpd.Model`の箱の同一性は`(lane, position)`。同じ箱への再訪問は自動的に同じ箱として扱われるため、正しい「箱数」は「distinct box数」（`len(box_id_of)`）であり、以前報告していた「run数」(`len(states)`)とは異なる。

## 比較した5つの抽象化（ログ0067）

| # | 抽象化 | 定義 | 真の箱数 |
|---|---|---|---|
| (1) | 車両物理サイズ基準 | 一様格子。cell=0.9526m（EGO/NPC半車長の和÷5）、near/farの区別なし | 320 |
| (2) | 一様格子ベースライン | 一様格子。cell=2.0m（車両サイズにも安全性モデルにも非依存の恣意的な値） | 158 |
| (3) | JAMA C&C述語抽象化 | 近傍=C&Cのrisk知覚フレーム前後・接触の有無で区切る／遠方(\|rx\|>40m)=単一のFAR箱 | **13** |
| (4) | RSS述語抽象化 | 近傍=RSSのviolation onset前後・接触の有無で区切る／遠方=単一のFAR箱 | **13** |
| (5) | 参考: 訂正前のC&C基準near/far計量格子 | near_rangeのみC&C onsetに連動、near_cell/far_cellは車両サイズ由来のまま | 91 |

安全性モデル自身のonsetフレーム: JAMA C&C = frame 588、RSS = frame 548（いずれも反実仮想シミュレーションで「予防可能」の判定は一致）。

## 主な知見

1. **述語抽象化は圧倒的にコンパクト。** (3)(4)はどちらも真の箱数13個——(1)(2)(5)のどの計量格子版（91〜320個）よりも大幅に少ない。「安全性モデルが実際に注意を払う範囲だけを、そのモデル自身の言葉で区切り、それ以外は1箱に潰す」というアプローチが、量的にも大きな効果を持つことが確認できた。
2. **purityは構造上必然。** (3)(4)は、自分自身のonsetに対して常にpureである——ラベルの定義自体がonsetフレームで切り替わるように作られているため、セルサイズのたまたまの一致に頼っていない((1)(2)(5)のような計量格子でpurityを達成しようとすると、セルサイズに対して非単調で、過学習のリスクを伴うことが分かっている——12.25節本文参照）。
3. **「車両サイズ基準」を徹底すると、near/farをやめて一様格子にすべき。** その場合、箱数はむしろ320個に増える（near/farの区別を導入していた(1)の元の45箱より遥かに多い）。近傍だけを細かくする意義自体は保たれるが、それは「車両サイズ」という原理単体からは出てこず、追加の設計判断が必要である。
4. **クロスモデルpurityは実務上重要ではない。** 各抽象化はそれが導かれた安全性モデルの文脈でのみ使われるため。

## 限界・今後の課題

- 1ログ(0067)のみの予備実験。12.24節と同じ10ログ規模での再現性確認が次のステップ。
- C&C述語抽象化の`RISK`状態がレーン(lane_k)によって9通りに分かれており、横方向の格子にヒステリシスを適用していないための細分化の疑いがある。
- RSSモデルは縦方向公式のみで、横方向（カットイン中の合流）公式は未実装。
- スケーラビリティ（Z3のmembership check）は箱数に強く依存することが12.24節で分かっており、述語抽象化（13箱）は計量格子（91〜320箱）よりも大幅に安価になると予想されるが、実測はまだ行っていない。
